# Current formula regression matrix

Captured 2026-10-09. Current implemented registry: **240** functions across **11** categories.

## Menu inventory is separate

The formula ribbon has 16 top-level controls: Insert Function, AutoSum, 11 category menus, Name Manager, Quick Create Names, and Recalculate. AutoSum contains SUM, AVERAGE, COUNT, MAX, MIN, SUMIF, and Other Functions. Category menus and the All Functions browser both derive their function entries from Core metadata.

Financial: 16; Logical: 11; Text: 28; Date: 22; Statistical: 33; Engineering: 20; Information: 14; Database: 12; Lookup: 24; Math: 53; Compatibility: 7

## Automated evidence

Existing calculation scenario files are reused for 142 functions. The bounded coverage file adds 98 independent cases for the original uncovered names, scalar-to-cell reference variants, registration/name checks for all 240 functions, below-minimum and above-maximum arity/error checks where applicable, and focused coercion/domain boundaries. Expected results are fixed hand calculations, existing assertions, or documented random bounds, never this engine's generated answers.

An additional 95 reference variants reuse existing assertion constants or small hand-calculated array/coordinate cases. All 233 functions that accept an argument have cell/range calculation evidence; the other seven are zero-argument functions. Reused expectations retain their original numeric tolerance and source link.

The JSON companion is the detailed per-function matrix: menu entry, implementation file/line, argument names and limits, tested input kinds, error scenarios, reference scenarios, boundary formulas, exact test links, and official-source provenance. Coverage means at least one independent calculation/error scenario for every current function, with explicit arity contracts; it does not mean every coercion, boundary, reference form, or application version is exhausted. Fields identify exactly which evidence exists.

## Bounded findings

- Filter/SUBTOTAL fixture: visible rows hold 10 and 9. Its asserted hidden intervals already establish the result 19. Correcting 20 to 19 repairs the assertion without changing calculation behavior.
- Independent HOUR(0.5) coverage found and repaired a genuine fractional-time extraction defect; shared calendar decomposition floored the serial. HOUR, MINUTE, and SECOND now preserve fractions while calendar helpers retain day truncation.
- No previous formula engine or XLSX engine is restored. Compatibility-lab continues to probe the public Core and native XLSX packages.

## Official comparisons

- SUBTOTAL: Both exclude filtered-out rows and nested subtotals. The filter regression fixture's visible 10 and 9 therefore sum to 19, not 20. [Excel](https://support.microsoft.com/en-us/excel/functions/subtotal-function); [WPS](https://www.wps.cn/learning/course/detail/id/158?sid=517)
- HOUR, MINUTE, SECOND: Both document the fractional-day time representation; 0.5 denotes noon. Time-part extraction must preserve fractions. Text time parsing remains outside the current strict numeric contract. [Excel](https://support.microsoft.com/en-us/excel/functions/hour-function); [WPS](https://www.wps.cn/learning/room/d/326896)
- PERCENTRANK.INC, PERCENTRANK.EXC, PERCENTRANK: Both document interpolation for nonmatching x; inclusive and exclusive endpoint formulas remain distinct. The symmetric middle fixture has an independently derived rank of 0.5 in either form. [Excel](https://support.microsoft.com/en-us/excel/functions/percentrank-exc-function); [WPS](https://www.wps.cn/learning/room/d/326873)
- MROUND: Official Microsoft worked example -10,-3 gives -9, opposite signs give NUM. Decimal midpoint ambiguities are intentionally not treated as an exact parity promise. [Excel](https://support.microsoft.com/en-us/excel/functions/mround-function); WPS behavior is not independently documented by this entry.
