# XLSX IO v1

`@idea10/xlsx-io` is a runtime-neutral byte adapter. It accepts `Uint8Array`, returns Core `Workbook` values, and never reads files, creates browser blobs, or replaces a document. Web owns the Worker, file chooser, confirmation and persistence transaction.

Conditional-format export compacts exact duplicate non-formula rules within each worksheet, retaining the first occurrence and the relative priority of remaining rules. It shares identical differential styles across worksheets and omits unused empty styles. Compaction affects only the export copy; the editable document and history remain unchanged. Formula rules are retained because volatile evaluations can differ. Distinct ranges, anchors, conditions and stop flags are preserved; ranges are never combined because that would change statistics-based rules.

Web does not display compatibility reports. Exports download directly; imports only confirm replacement of the current document and local copy. Processing failures use a short dismissible error dialog. Compatibility diagnostics remain internal to the adapter for development tests and documentation, not as user-facing warnings or an export confirmation step.

V1 maps worksheets, literal values, raw formula source, supported font/fill/alignment/border styles, dimensions, merges, frozen panes, conditional formatting and the 1900/1904 date system. Conditional formatting retains ordered priority, ranges, anchors, `stopIfTrue`, custom formulas, literal and formula cell comparisons, text, blank, duplicate/unique, top/bottom ranks, above/below average, date periods, data bars, two/three-color scales, and all 20 icon sets. Differential styles retain supported number formats, font properties, pattern or gradient fills, and borders, including explicit boolean/font-script/border clears. It retains Core threshold types (`min`, `max`, numeric, percent, percentile, formula), data-bar and icon value visibility, and icon reversal. Formula source is retained verbatim apart from the XLSX leading `=` convention; cell-comparison formula operands are rebased to their exported sqref anchor, while visual formula thresholds use only absolute references. The `x14` extension carries `3Stars`, `3Triangles`, and `5Boxes`; Core minimum and maximum icon thresholds are encoded as equivalent 0% and 100% x14 thresholds. A differential fill is atomic in XLSX, so clearing only a pattern or gradient while preserving an unknown base fill is reported rather than approximated. Negative/gradient data bars, custom bar lengths or axes, strict (`gte="0"`) thresholds, auto thresholds, custom icon mappings, and unsupported differential-style fields are reported as omissions rather than silently changed. Imported formula result caches are discarded and never treated as fresh truth. On export, the adapter evaluates only Core-supported, parseable formulas with Core-supported dependencies and writes that fresh result as a cache. It asks Excel to fully recalculate on open. Formulas with parse failures, cycles, unknown functions, or dependencies on any of those remain uncached and are reported as not calculated.

Number formats cover General, number, currency, accounting, date, time, percentage, fraction, scientific, text, special and custom categories. Core owns their normalized state and shared `numfmt@3.2.6` renderer. Supported codes retain conditions, colors, fill directives, locale tokens and Chinese DBNum1/DBNum2 modifiers. Import uses semantic fields when re-export preserves their meaning, otherwise retaining the original code. Malformed or unsupported codes produce an omission diagnostic. After import preflight, a narrow worksheet XML view follows workbook relationship order to recover numeric dates that ExcelJS converted to JavaScript Dates, preserving serials 0 and 60 and sub-millisecond fractions. UI date/time presets carry their Chinese or US locale tokens through XLSX.

Image export takes prepared raster resources through `encodeXlsx(workbook, { images })`. Web resolves each referenced image from the local asset store using the captured workbook snapshot, keeps unchanged PNG/JPEG/GIF bytes, and rasterizes WebP or cropped/rotated/flipped variants to PNG. Rasterization is bounded to 4096 pixels per side and 16 megapixels. The runtime-neutral adapter embeds those bytes and deduplicates matching asset/transform variants across sheets. Floating pictures use standard one-cell anchors with physical width/height and native EMU offsets, so their size does not depend on a second grid endpoint. Cell pictures use Excel's native rich-data in-cell image type, including metadata, media relationships and alternate text, with no floating drawing substitute. This requires a viewer supporting Excel's Place in Cell feature; older Excel versions may show `#VALUE!` and WPS support depends on the version. Missing resources fail the export instead of silently dropping pictures. The Web export timeout covers both image preparation and the Worker conversion. Image import is not included in this support; the existing drawings/media import block remains in place.

Export finalization uses `fflate/browser` only on the newly generated archive: it removes ExcelJS's invalid `editAs` attribute from one-cell anchors, detaches the Normal font from theme/script substitution, and adds native image metadata. It does not bypass import preflight or process imported archives directly. Standard ZIP directory entries are omitted; media bytes are not recompressed. See [Microsoft local-image rich values](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-xlsx/aac1e2a6-7072-4e66-b1de-f20b8bf63318) and [XlsxWriter's embed-image support](https://xlsxwriter.readthedocs.io/worksheet.html#worksheet-embed-image).

Font-size import/export preserves the number displayed by the font-size control: 12 exports as Excel/WPS size 12 and imports as size 12, with no 3/4 or 4/3 conversion. Excel stores this number in points while Web currently renders its number as CSS pixels; this is numeric parity, not a claim of pixel-identical typography. Tests cover all supported integer sizes 8 through 72. Fractional sizes from external files remain approximate because the pinned ExcelJS 4.4 decoder truncates them and Core accepts integer sizes. Export always writes the effective vertical alignment, including Core's implicit middle alignment, because XLSX defaults to bottom when the field is absent. Horizontal alignment and wrapping are retained independently.

Decode performs finite ZIP preflight before ExcelJS loads a document: central/local headers, path safety, encryption, compression, entry counts, declared and actual inflated sizes, and unsupported parts. It bounds ordinary ZIP bombs but is not a claim that malformed compression is harmless; Web must still use worker isolation and timeout. Preflight only inspects UTF-8 XML; DTDs, entities defined by DTDs, UTF-16, and other declared encodings are rejected. Standard XML character entities are decoded before relationship attributes are evaluated, so encoded `TargetMode="External"` cannot bypass the external-content block.

Diagnostics are returned in `XlsxCompatibilityReport` for development use. Macros, drawings/media, external links, encryption, malformed archives and resource limits still block import. Filters, unsupported number-format codes and style fields, unsupported conditional-formatting rules, and imported formula caches are recorded as losses. Four-sided borders and matching diagonal borders map directly; two Core diagonal borders with different style or color cannot be represented as one XLSX diagonal. Core row pixels convert exactly to XLSX points at 96 DPI. All materialized rows, including styled blanks and merge rows, explicitly carry their height to prevent font-based auto-sizing; untouched gaps remain sparse. Custom column widths use the Open XML 1/256-character conversion with an explicit unthemed Calibri 11 / 96 DPI / 7-pixel maximum-digit-width Normal font. Tests cover every supported integer Core column width and verify this font declaration. Body fonts are complete name/size records that preserve the selected size number, with Calibri as the adapter's fallback when no font name is specified. Imports use the same column-width baseline; other Normal fonts remain a documented approximation without additional font detection machinery. The bounded workbook and worksheet XML inspection also records omitted defined names, data validation, protection, hidden sheets/rows/columns, hyperlinks, manual breaks, headers/footers, and custom print settings. Default page margins and ExcelJS's default page setup attributes do not create a loss diagnostic. Export always creates a new file.
