# XLSX IO v1

`@idea10/xlsx-io` is a runtime-neutral byte adapter. It accepts `Uint8Array`, returns Core `Workbook` values, and never reads files, creates browser blobs, or replaces a document. Web owns the Worker, file chooser, confirmation and persistence transaction.

Web does not display compatibility reports. Exports download directly; imports only confirm replacement of the current document and local copy. Processing failures use a short dismissible error dialog. Compatibility diagnostics remain internal to the adapter for development tests and documentation, not as user-facing warnings or an export confirmation step.

V1 maps worksheets, literal values, raw formula source, canonical number/percent/currency formats, supported font/fill/alignment/border styles, dimensions, merges, frozen panes and the 1900/1904 date system. Imported formula result caches are discarded and never treated as fresh truth. On export, the adapter evaluates only Core-supported, parseable formulas with Core-supported dependencies and writes that fresh result as a cache. It asks Excel to fully recalculate on open. Formulas with parse failures, cycles, unknown functions, or dependencies on any of those remain uncached and are reported as not calculated.

Decode performs finite ZIP preflight before ExcelJS loads a document: central/local headers, path safety, encryption, compression, entry counts, declared and actual inflated sizes, and unsupported parts. It bounds ordinary ZIP bombs but is not a claim that malformed compression is harmless; Web must still use worker isolation and timeout. Preflight only inspects UTF-8 XML; DTDs, entities defined by DTDs, UTF-16, and other declared encodings are rejected. Standard XML character entities are decoded before relationship attributes are evaluated, so encoded `TargetMode="External"` cannot bypass the external-content block.

Diagnostics are returned in `XlsxCompatibilityReport` for development use. Macros, drawings/media, external links, encryption, malformed archives and resource limits still block import. Filters, images, custom number formats, unsupported style fields and imported formula caches are recorded as losses. Four-sided borders and matching diagonal borders map directly; two Core diagonal borders with different style or color cannot be represented as one XLSX diagonal. Core row pixels convert exactly to XLSX points when the value is on the 0.75-point grid. Custom column widths use the Open XML 1/256-character conversion with the exported Calibri 11 / 96 DPI / 7-pixel maximum-digit-width baseline. Tests cover every supported integer Core column width and verify the file's Normal font. Imports use that same baseline; other Normal fonts remain a documented approximation without additional font detection machinery. The bounded workbook and worksheet XML inspection also records omitted defined names, data validation, conditional formatting, protection, hidden sheets/rows/columns, hyperlinks, manual breaks, headers/footers, and custom print settings. Default page margins and ExcelJS's default page setup attributes do not create a loss diagnostic. Export always creates a new file.
