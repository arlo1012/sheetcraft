# XLSX IO v1

`@idea10/xlsx-io` is a runtime-neutral byte adapter. It accepts `Uint8Array`, returns Core `Workbook` values, and never reads files, creates browser blobs, or replaces a document. Web owns the Worker, file chooser, confirmation and persistence transaction.

Web shows compatibility details only inside import/export confirmation dialogs. Blocking errors also use a dismissible dialog. Completed or cancelled operations leave no inline status banner or compatibility report in the spreadsheet layout; exports with no compatibility issues download directly.

V1 maps worksheets, literal values, raw formula source, canonical number/percent/currency formats, supported font/fill/alignment/border styles, dimensions, merges, frozen panes and the 1900/1904 date system. Imported formula result caches are discarded and never treated as fresh truth. On export, the adapter evaluates only Core-supported, parseable formulas with Core-supported dependencies and writes that fresh result as a cache. It asks Excel to fully recalculate on open. Formulas with parse failures, cycles, unknown functions, or dependencies on any of those remain uncached and are reported as not calculated.

Decode performs finite ZIP preflight before ExcelJS loads a document: central/local headers, path safety, encryption, compression, entry counts, declared and actual inflated sizes, and unsupported parts. It bounds ordinary ZIP bombs but is not a claim that malformed compression is harmless; Web must still use worker isolation and timeout. Preflight only inspects UTF-8 XML; DTDs, entities defined by DTDs, UTF-16, and other declared encodings are rejected. Standard XML character entities are decoded before relationship attributes are evaluated, so encoded `TargetMode="External"` cannot bypass the external-content block.

Warnings are returned in `XlsxCompatibilityReport`; Web must show them before replacement. Macros, drawings/media, external links, encryption, malformed archives and resource limits block import. Filters, images, custom number formats, unsupported style fields and imported formula caches are reported as losses. Four-sided borders and matching diagonal borders map directly; two Core diagonal borders with different style or color cannot be represented as one XLSX diagonal and are reported as a style loss. Core row pixels convert exactly to XLSX points when the value is on the 0.75-point grid. Column pixels use a font-dependent Excel character-width conversion and remain an explicit approximation warning. The bounded workbook and worksheet XML inspection also reports omitted defined names, data validation, conditional formatting, protection, hidden sheets/rows/columns, hyperlinks, manual breaks, headers/footers, and custom print settings. Default page margins and ExcelJS's default page setup attributes do not create a loss warning. Export always creates a new file.
